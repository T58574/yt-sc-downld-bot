# docs/ — база знаний по продукту

Здесь лежит всё, что мы **уже посчитали, измерили и решили**. Цель — чтобы любой следующий
заход в проект не начинался с «а сколько стоит обработка?», «а что с лимитами Telegram?»
и «а мы вообще decided, какой тариф?».

## Нейминг

| Правило | Формат | Пример |
|---|---|---|
| Документ раздела | `docs/NN-topic.md`, `NN` = порядковый номер раздела (двузначный) | `docs/20-unit-economics.md` |
| Разделы нумеруются по жизненному циклу продукта | 00 → 90 | продукт → деньги → платежи → лимиты → риски → рост → бренд → план → решения |
| Замер с датой | `docs/benchmarks/YYYY-MM-DD-<что>.md` | `docs/benchmarks/2026-10-21-raw-measurements.md` |
| Решение | запись `D-NNN` в `docs/90-decisions.md` | `D-004 Кредитная модель вместо подписки на старте` |
| Скрипт замера | `scripts/bench/<что>-bench.mjs` / `.sh` | `scripts/bench/upload-throughput-bench.mjs` |

Правило: **новый факт — новая запись в `90-decisions.md`**, новый замер — файл в
`benchmarks/` с датой + ссылка из `20-unit-economics.md`. Разделы не переписываются
под новые цифры, а дополняются датированными блоками «Перепроверено YYYY-MM-DD».

## Что уже измерено (не перемеривать)

- Себестоимость одной обработки ≈ **$0.0005** (или ≈$0 при безлимитном трафике) → [20-unit-economics.md](20-unit-economics.md)
- Отправка в Telegram ускоряется **в 7 раз** при 16 воркерах (2.0 → 14.7 МиБ/с) → [40-telegram-limits.md](40-telegram-limits.md)
- Перекодировать в 360p **не надо**: в YouTube есть нативный 360p → [00-product.md](00-product.md)
- Перекодирование 1080p60→360p стоит 419 CPU-сек — в 70 раз дороже скачивания → [20-unit-economics.md](20-unit-economics.md)
- В Telegram есть **нативные подписки в Stars** (30 дней, автосписание) → [30-payments.md](30-payments.md)
- Включение **topics в личных чатах отнимает 15% Stars-выручки** → не включаем → [30-payments.md](30-payments.md)
