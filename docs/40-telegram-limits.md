# 40 — Лимиты Telegram и «как не потерять аккаунт»

> Источники: `core.telegram.org/bots/faq`, `core.telegram.org/api/files`,
> `core.telegram.org/bots/api` (Bot API 10.3, 24.08.2026),
> `telegram.org/tos/bot-developers`.
> Свои замеры: [benchmarks/2026-10-21-raw-measurements.md](benchmarks/2026-10-21-raw-measurements.md).

## Официальные лимиты (цитаты из документации)

### Частоты сообщений (Bot FAQ)

| Что | Лимит | Что будет при превышении |
|---|---|---|
| Один чат (личный) | **1 сообщение/сек** | `429` |
| Группа | **20 сообщений/мин** | `429` |
| Broadcast по подписчикам | **~30 сообщений/сек** | `429` |
| Платный broadcast (`allow_paid_broadcast`) | до 1000/сек, 0.1 ⭐ за сообщение сверх 30/сек | нужно ≥100 000 ⭐ на балансе и ≥100 000 MAU |

### Файлы

| Что | Лимит |
|---|---|
| Bot API, облако | multipart: 10 МиБ фото / **50 МиБ** прочее; по URL: 5/20 МиБ |
| Bot API, `getFile` | **20 МиБ** (только чтение) |
| Bot API, локальный сервер (telegram-bot-api) | загрузка до **2000 МиБ**, скачивание без лимита |
| MTProto | часть ≤ **512 КиБ**, шаг 512 КиБ, максимум частей — из `upload_max_fileparts_default` (для бота = 4000) → **2000 МиБ** |
| `FLOOD_WAIT_X` | повторить запрос через X секунд |
| `FLOOD_PREMIUM_WAIT_X` | скорость загрузки ограничена (нет Premium). Боты Premium не бывают → потолок существует |

### Про параллельную загрузку — прямо из документации

`core.telegram.org/api/files`: *«To further increase time efficiency, we recommend using
a local call queue… To upload multiple chunks in parallel, multiple parallel call queues
(linked to separate TCP connections to the datacenters) can be used.»*

То есть параллельная загрузка чанков по нескольким TCP-соединениям — **официально
рекомендованный** Telegram паттерн, а не обход лимитов. Наши замеры это подтверждают:
4 воркера → 2.0 МиБ/с, 16 воркеров → 14.7 МиБ/с.

## Наши замеры скорости отправки (200 МиБ, DC3 149.154.167.41)

| Воркеров | Время | Скорость | Комментарий |
|---|---|---|---|
| 4 (текущее значение в коде) | 99.6 с | 2.0 МиБ/с | файл 256 МиБ едет ~2 мин |
| 8 | 48.7 с | 4.1 МиБ/с | |
| **16** | 13.6 / 15.8 с | **14.7 / 12.7 МиБ/с** | оптимум, файл 256 МиБ едет ~20 с |
| 32 | 38.7 с | 5.2 МиБ/с | деградация — жёстче душит |

Потолок: **~13–15 МиБ/с суммарно на один бот/IP**. Это ~180 файлов по 256 МиБ в час
теоретически. На практике Telegram режет агрегат, поэтому **рабочая гипотеза:
50–100 отправок в сутки на бот** (проверяется нагрузочным тестом, Этап 0).

## Правила, чтобы не получить бан

1. **На FLOOD_WAIT — только backoff.** Никогда не увеличивать параллелизм в ответ на
   flood-ошибку. Это прямая линия к бану.
2. **Не более 1 сообщения/сек в чат, 20/мин в группе, 30/сек broadcast.** Прогресс
   правится редко (у нас `PROGRESS_UPDATE_INTERVAL_MS=2000`) — это в норме.
3. **Отправка файлов: 12–16 воркеров.** Не 32+, не 1.
4. **Не использовать чужие Bot API credentials** (ToS §5.2 f) — прямо запрещено.
5. **Не спамить уведомлениями** (§5.2 b): никаких «вы давно не качали» по ночам.
6. **Минимум данных + удаление по запросу** (§4.2): `/deleteaccount`, автоочистка логов.
   Данные — шифровать at rest, отдельно от ключа (§4.4).
7. **Не включать topics в личных чатах.** За это Telegram удерживает **15% от Stars-покупок**
   (ToS §6.2.6). Нам они не нужны → не включаем → не теряем 15% выручки.
8. **Продавать цифровые товары внутри Telegram только за Stars** (§6.2). Альтернативные
   способы оплаты — только на сайте (→ [30-payments.md](30-payments.md)).
9. **Пул ботов — это резервирование, а не обход санкций.** Несколько ботов на разных
   аккаунтах для отказоустойчивости и распределения нагрузки — нормально. Создавать
   нового бота, чтобы обойти конкретный бан — нарушение §5.2 f.
10. **Владелец ботов: 2FA на аккаунте, токены и MTProto-сессии в секретах, бэкап сессий.**
    Потеря аккаунта-владельца = потеря всех ботов (ToS §6.3).

## Что делаем для устойчивости

| Мера | Стоимость | Приоритет |
|---|---|---|
| Бэкап MTProto-сессий и токенов | 0 | сразу |
| 2FA на аккаунте-владельце | 0 | сразу |
| Пул из 2–3 ботов | 0 (нужен ещё номер/SIM для аккаунтов) | после Этапа 1 |
| Нагрузочный тест: где начинается FLOOD_WAIT | ~1 час | Этап 0 |
| Мониторинг: время доставки, FLOOD_WAIT, ошибки | ~0 | Этап 1 |
| Ротация IP (второй VPS) | €7/мес | когда упрёмся |

## Чего НЕ делаем

- Не включаем paid broadcasts без нужды (0.1 ⭐ за сообщение).
- Не гоним «миллион сообщений» — нам нужны платящие, а не объём.
- Не строим функции массовой рассылки файлов.
